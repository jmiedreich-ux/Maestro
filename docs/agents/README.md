# Maestro Agent Roles

Every agent must follow the repository-wide rules in [AGENTS.md](../../AGENTS.md), the joined project's approved engineering policy, and the exact work assignment.

## Authority order

1. Repository-wide working rules.
2. Joined-project architecture, product decisions, and engineering policy.
3. The approved work assignment.
4. The applicable role contract.
5. Any project-specific specialist overlay.

A lower level may add restrictions but cannot weaken a higher level. If two authorities conflict, the agent stops and reports the conflict.

## Roles

Registration uses the Project Architect and Decision Fidelity Reviewer under the architecture's registration rules. Execution roles use the exact configured routes, saved state and result contracts under [Execution](../architecture.md#execution). The [Development Manager](maestro-development-manager.md) manages work flow; the [Integration Manager](integration-agent.md) owns code integration; independent implementation review, isolated milestone Quality Assurance, strict FIFO integration, correction supplements, dependency delivery, milestone promotion and immutable completion records follow the architecture. Executable handlers, schemas and installed verification remain implementation work. Role text cannot add authority to registration or bypass the service contract.

## Contract standard

Every role contract states its purpose, required inputs, authority, prohibitions, eligible work, evidence, handoff, escalation conditions, and resource restrictions. Each run records the exact role-contract revision it used.
