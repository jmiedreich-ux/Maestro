# M3 registration runtime prerequisite amendment

Status: approved Owner-directed amendment. This record is part of the M3 manual architecture.

## Shared runtime prerequisite

Before M3 Registration assessment resumes, Maestro must construct one service-owned configured agent-route provider from `/etc/maestro/agents.toml`, expose it to installed process plugins, and deliver supervisor-confirmed adapter runtime identity only to the matching reserved operation callback. Missing or unverifiable configuration blocks the affected start; no default route, identity argument, fallback, or second registry is allowed.

## M3 intake rehydration

Exact source intake persists an immutable successful record including normalized repository, selection-decision reference, source selection/ref/commit, overview, publication branch, provider snapshot/evidence, and complete ordered source inventory. Failed attempts have no inventory and never reread a source during rehydration.

## M3 assessment composition

Registration assessment consumes only that saved intake record. The installed service registers `registration.start` using the configured provider. It reserves and supervises role runs; only supervisor callback metadata for the saved operation can establish runtime identity. Recovery rehydrates saved state without source reread or caller-supplied repository, decision, inventory, or identity.

## Order

1. Shared runtime prerequisite.
2. M3 source-intake rehydration correction.
3. M3 registration assessment correction.
