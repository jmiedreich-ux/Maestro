# Maestro manual architecture — QA resource preparation

Draft resource proposal, version 1. No resource is installed, provisioned, selected from a verified catalog or approved for use by this document.

## Why this input is needed

[Project Quality Assurance bindings](../../architecture.md#project-quality-assurance-bindings) requires an operator-provided, non-secret catalog before drafting QA plans that use environments, credentials or network access. An entirely self-contained plan may use empty references and a null binding hash. That exception cannot be used for acceptance requiring actual GitHub publication, installed agents or credentialed service behavior.

The manual planning adaptation does not fabricate a service-owned catalog, its project identity/hash, test credentials or installed availability. The confirmed registration covers outcomes; it does not select these resources. The resource gap blocks affected QA-plan completion and the final breakdown-confirmation claim, not source investigation or the draft work map.

## Minimum non-secret catalog information

For each provided environment: unique name, `classification: test`, non-secret variables, allowed secret names and network-dependency names. For each network dependency: exact host, protocol and allowed ports. For each secret: its public catalog name and test classification; the operator/service retains its credential locator privately. The operator must establish availability and authorization without revealing values.

For manual planning, retain an operator-supplied non-secret description with provenance and clearly label its evidence level; do not call it a service-validated `qa-catalog.json` or use an invented hash. If live Maestro is later used, its service must collect, validate and bind the actual snapshot through the defined assignment contract. Any mismatch then blocks import/use instead of silently translating a manual proposal into runtime authority.

## Work that can proceed without it

Investigating and structuring source, defining packet scopes and dependency edges, identifying needed setup tooling, and specifying which real journeys require evidence can proceed. Self-contained deterministic tests can be specified without external names. The final selected setup commands, environment/secret/network references and binding evidence for non-self-contained milestone QA cannot be completed until the catalog is available.
