# Review, amend and confirm the work breakdown

## Outcome and result
Closes [Review and confirm the development breakdown](../../outcomes/architecture-loop.md#review-and-confirm-the-development-breakdown): after a breakdown is saved, a separate reviewer checks the exact published set against the confirmed outcomes, the architect amends it in the same persistent session when the review finds a blocking defect, and the Owner confirms one exact reviewed version from the terminal. The loop then completes without scheduling or starting Execution.

## Existing implementation assessment
Reused as built: the architecture activity and its step machine, the persistent architect session, the agent run service with its recovery allowance, the finding identity table, the journaled GitHub publication and discovery index, the `architecture-breakdown@1` schema (it already defines `review`, `confirmation`, `confirmPayload` and `view`), the shared `owner.decision` request, and the terminal's two-step cancel pattern. Gaps found: the activity stopped at `saved`; the architecture response contract forced the reviewer fields to null; the reviewer transport check required registration artifacts; there was no review record, review counting, amendment pass, limit decision, confirmation operation or completion; `owner.decision` was owned by registration alone.

## Decisions
- A saved breakdown moves to a `reviewer` state in the same activity. The reviewer is a fresh run (no persistent session), role `fidelity_reviewer`, with the exact published records, the confirmed outcomes and the recorded decisions as inputs, and returns `review_outcome`, `reviewed_set` (manifest and content hash, checked against the working reference) and findings in its response. It writes no files.
- The service, not the reviewer, writes the `review` record from the response, so its findings get stable identities and the record always satisfies the saved schema. The record and the updated manifest (stage `reviewed`, review added to the inventory) are added to the reviewed version in one journaled commit, then the discovery index in a second commit. The reviewed content hash does not change.
- One completed review consumes one round. Technical failures, invalid responses and duplicate delivery do not. The limit is the snapshotted `maximum_fidelity_reviews` plus recorded Owner grants.
- REQUEST_CHANGES with rounds left returns the findings to the same architect session as an amendment pass that writes the complete `breakdown.json` again; the existing versioned set builder rewrites only records whose content or links changed and publishes the next version. The next review is told what it found before and which records were rewritten.
- At the limit with blocking findings the activity pauses and the Owner decides through `owner.decision` (`fidelity_review`, `grant_one` or `remain_paused`); one grant adds one round and cannot force approval. The single `owner.decision` operation is shared with registration and routed by activity.
- `architecture.confirm` compares the expected working reference (version, commit, manifest path and hash, reviewed content hash) and the covering review before it saves the request and reserves the operation; a stale reference is refused with the current one. Accepted limitations are the passing review's non-blocking findings, cited by exact finding reference. `confirmation.json` and the updated manifest (stage `confirmed`) are published, then the index with its confirmed reference; only then does SQL record the confirmed reference, complete the activity and release the project. A pending confirmation cannot be cancelled.
- Terminal: `/architecture` shows review state, and Confirm first shows the exact version, coverage, dependencies, parallel opportunities and limitations, then needs a second deliberate action. `/architecture full` lists every saved record. Grant and Remain paused are explicit actions.

## Verification
Unit tests in `tests/maestro/service/test_architecture_review.py` and `tests/maestro/terminal/test_terminal_architecture.py`; real proof on a disposable service with real Codex and Claude Code agents and a real repository under `var/qa/architecture-live/`.
