## Current position

The architecture and both declarations use the Planning Guide structure. The project overview identifies their authoritative locations. Architecture journeys explain interface results; declarations reference those journeys and state completion evidence and dependencies.

CLI foundation implementation precedes registration; final connected CLI acceptance is shared with real registration integration. The initial registration scope uses the CLI; the command center remains excluded. These documents specify proposed outcomes and do not establish implementation completion or successful registration.

## Outstanding design

The architecture and declarations identify the unresolved mechanisms at their authoritative locations. Registration supplies initial projects and questions. Activity selection, registration labels, connection configuration, retry, request/events, answer reconciliation, and terminal dimensions are defined in the architecture. Agent contracts, persistence consistency, registration formats, and work-state enforcement remain explicit dependencies.

The agreed following topics are the Project Architect and Fidelity Reviewer roles, then Model Execution Adapters. Consult the current sources before continuing; do not infer answers from the consolidated information review.

## Working rules

Commit authorized changes directly to `master`. Keep system behavior in architecture and delivery outcomes in declarations. Follow the Planning Guide for naming and source structure. Apply review corrections to authoritative documents without creating separate review reports.
